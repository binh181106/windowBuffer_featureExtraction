# ECG demo data — source & conversion

## Source (REAL data, not synthetic)

- **Dataset**: PhysioNet MIT-BIH Arrhythmia Database
  - URL: https://physionet.org/physiobanks/database/25/mitdb/ (files v1.0.0)
  - Downloaded (2026-10-31) from the PhysioNet S3 mirror:
    `https://physionet-open.s3.amazonaws.com/mitdb/1.0.0/100.dat` (1 950 000 B)
    and `100.hea`.
- **Record**: `100`, **channel 1 (MLII)** — channel index 0 in the file.
  Per the official MIT-BIH record annotation, record 100 is **normal sinus
  rhythm**, 60-yr male. No arrhythmia label is derived from this project —
  no RR / heart-rate / diagnosis is inferred from the RTL threshold crossings.
- **Sample rate**: 360 sps (matches the pipeline's 360 Hz target exactly).
- **Raw format**: WFDB `212` — **signed 12-bit, 2 samples packed in 3 bytes**
  (as declared in `100.hea` field 3). File is 1 950 000 B = 650 000 samples/ch
  × 2 ch × 12 bit / 8 — the NATIVE format, no conversion step. Decoded range
  is −2048..+2047.
- **`.hea` channel fields (verbatim, ch MLII):** `212 200 11 1024 995
  -22131 0 MLII` → gain = **200 ADC units/mV (= 5 µV per LSB)**, data bits = 11,
  **digital offset (ADC zero) = 1024**, **initial value = 995**, baseline =
  −22131 µV, zero-based = 0. Do not read 995 as a "baseline": it is the first
  raw sample; 1024 is the zero.
- **Decode check (2026-11-01)**: ch0[0] = 995 = the .hea initial value (MLII)
  → 212 framing correct. A (previously used) int16 mis-decode gives
  −32717..+32681 and a repeating 3-sample byte-frame pattern = corrupted, not
  ECG. `demo/test_ecg_convert.py` locks the 212 bit-packing with hand-derived
  fixtures (negatives + edges 0/2047/−1/−2048) and rejects incomplete groups.
- **Segment statistics (independently recomputed, ch0, samples 1000..3047,
  N = 2048):** raw12 min = 907, max = 1213, p2p = 306 units = 1.53 mV at
  5 µV/unit (200 units/mV). This is the *digital* p2p of the 8-bit-mapped
  segment; it is not a clinical amplitude claim.
- **Segment**: samples **1000 .. 3047** (N = 2048) — 8 complete 512-sample
  windows at stride 256 (512, 768, …, 2048). ≥ 3 windows satisfied.

## 12-bit → 8-bit conversion

The pipeline's ADC path is 8-bit. The raw signed-12-bit waveform is mapped
**linearly into 0..255** (the ECG shape is preserved):

```
out8 = clamp( round((raw − min_seg) · 255 / (max_seg − min_seg)) , 0, 255 )
min_seg = 907,  max_seg = 1213   (per this 212-decoded segment, record 100 ch0)
```

- No per-window normalization, no threshold-tuning of the data.
- Script (re-runnable, deterministic): `demo/ecg_convert.py`
  (`python -I demo/ecg_convert.py --start 1000 --n 2048 --channel 0
   --out demo/ecg_rom.hex`). It cross-checks the .hea (record/channel/sample
  count) and hard-fails on a truncated 212 file (explicit data-loss policy).
- Output: `demo/ecg_rom.hex`, one 2-hex-digit sample per line, 2048 lines.
- 8-bit stats: min = 0, max = 255 (extremes map to the ends by construction).

## Expected distortion (reported, NOT corrected)

Downstream `window_buffer` subtracts `BASELINE_OFFSET = 169` and clamps
`sample < 169 → 0`. Our post-base values are therefore **0..86 only**
(sign-extended → +0..+86):

- `f_zc` (zero-crossings via bit7 of the 8-bit sample) will be **0** for every
  window — the bit7 of 0..86 is never set. This is a known open item
  (AUTOMATION_STATUS §4 "f_zc / f_half_ratio"), reported honestly, not a bug
  introduced here.
- `f_crest` uses the as-RTL truncated expression (16-bit numerator) — same
  open item as tb feature Test 8; golden mirrors the RTL bit-exactly.
- The 8-bit clamp crushes the negative half of the ECG (values below the
  post-base midpoint are 0). This is the known baseline-clamp behavior of the
  pipeline, not a data-conversion artifact.

## Golden expectations

- `demo/golden_model.py` recomputes the 12 features **independently** (Python,
  mirroring the RTL formulas bit-for-bit, including the as-RTL crest
  truncation and the `f_var`/`f_rms` truncation) from the **on-disk
  `ecg_rom.hex`** (regenerated by `ecg_convert.py` from the 212 .dat), then
  generates:
  - `demo/golden/expected_packets.sv` — SystemVerilog include arrays of the
    expected 12 features per window + expected class (placeholder zero
    weights ⇒ class 0) used by the demo testbench.
  - `demo/golden/expected_packets.json` — machine-readable golden for the
    Python decode/compare scripts (`demo/uart_decode.py`)).
- The demo testbench must be compared against these files, **not** against a
  captured DUT output.
